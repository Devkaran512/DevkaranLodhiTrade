# Deploy DevkaranLodhiTrade backend on Render

This project includes `render.yaml` for a FastAPI web service. The backend is prediction-only and has no Groww login, token, order placement, or broker execution.

## 1. Push the project to GitHub

Use the Git commands in the main README. The repository should contain `render.yaml` at its root and the `backend/` folder.

## 2. Connect GitHub to Render

In Render Dashboard, create a new Blueprint from the GitHub repository `DevkaranLodhiTrade`.

Render will read `render.yaml`, build the Python service from `backend/`, and start FastAPI on Render's `$PORT`.

## 3. API key

`render.yaml` uses `generateValue: true` for `BACKEND_API_KEY`, so the secret is generated by Render instead of being committed to Git.

After the first deploy, open the service's Environment page and copy the generated `BACKEND_API_KEY` value for use in the Android app.

## 4. Backend URL

After deployment, Render gives the service a URL similar to:

`https://devkaranlodhitrade-api.onrender.com`

Do not copy this example URL unless it is the URL Render actually assigned to your service.

## 5. Test

Open:

`https://YOUR-RENDER-URL/health`

Expected response includes:

`{"status":"ok","mode":"prediction-only","groww":false,"demo":false}`

The `/signal` endpoint requires the `X-API-Key` HTTP header.

## 6. Android

In the APK:

- Backend URL = your actual Render HTTPS URL
- Backend API key = the generated Render `BACKEND_API_KEY`

Then tap `START LIVE SIGNAL`.

## Important

Render free web services can spin down after inactivity, so the first request after idle can take longer. For production-grade continuous market-data latency, use a suitable always-on plan and preferably a licensed real-time data feed.

## V19 learning-memory note

V19 does not require a paid database. The learning/event journal is bounded in-process memory so it remains compatible with the Render Free plan. Render restarts/spin-downs can clear it. The API explicitly reports that storage policy to the app. Do not describe this as permanent cloud memory until a durable database is added and validated.
